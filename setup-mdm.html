Deploy through your MDM

For IT teams with a device console. Push the app, the kiosk lock, and every setting including the room and the credential. An iPad goes from the box to the board with nobody touching it.

Print this page with ⌘P. Links print with their addresses.

Before you start

Three prerequisites, each done once per organization. Bored Room reads the standard Managed App Configuration dictionary (com.apple.configuration.managed); every key is optional, and any key you set is locked on the device.

A. Google: one service account, shared with every room

Full click-by-click in the by-hand guide, sections A and B. Summary:

  1. Cloud Console › project › enable Google Calendar API › IAM & Admin › Service Accounts › create (no roles) › Keys › Add key › JSON. Keep the file; it's the credential you'll push. Google Cloud organizations created since May 2024 block key creation by default (iam.managed.disableServiceAccountKeyCreation); override it on the project under IAM & Admin › Organization Policies, as the by-hand guide shows.
  2. Admin console › Apps › Google Workspace › Calendar › Sharing settings › General settings card › External sharing options for secondary calendars › "Share all information, but outsiders cannot change calendars" (or "…and outsiders can change calendars" if you'll enable booking). Can take up to 24 hours to apply.
  3. Share each room with the service account email: See event details, or Make changes and see event details for booking (older labels: "See all event details" / "Make changes to events"). Do this in Google Calendar (room › Settings and sharing › Shared with) or with the Calendar API's acl.insert (role reader or writer; writerWithoutPrivateAccess also works for booking) if you're scripting many rooms.
  4. Collect each room's calendar ID: in Google Calendar, the room › Settings and sharing › Integrate calendar › Calendar ID, e.g. c_1882c…@resource.calendar.google.com (the Admin console shows the same value as the resource's email). A spreadsheet of serial, room name, calendar ID is all the per-device data you'll need.

B. Apple Business Manager: licenses

  1. Apps and Books › Bored Room › quantity › Get. 99¢ per copy.
  2. Assign the licenses to the location your MDM server token belongs to.
  3. In the MDM, sync Apps and Books so the app appears in your catalog.

C. MDM: supervision and device settings

  1. Single App Mode requires supervised iPads. Use Automated Device Enrollment (devices added to Business Manager by the reseller or with Configurator for iPhone) or supervise with Apple Configurator.
  2. A Restrictions or device-settings payload that turns auto-brightness off, so iPadOS doesn't undo the after-hours dimming. Auto-Lock: Never (Single App Mode's own option covers this too).
  3. Decide your schedule policy now: always on, or days and hours. If you push none of the hours keys, the default applies: Monday to Friday, 07:00 to 17:00, dark otherwise.

Checklist

  • Service account key file in hand; sharing setting changed; every room shared; calendar IDs collected (A)
  • Licenses bought, assigned to the MDM's location, synced into the catalog (B)
  • Supervision path chosen; auto-brightness-off payload ready; hours policy decided (C)

Configure the MDM

App

  • Bundle ID: com.dmarcantonio.RoomBoard (the App Store name is Bored Room; the bundle ID predates the rename).
  • Distribution: device-based. The iPads need no Apple ID.
  • Automatic updates: on. Remove app on unenrollment: your policy.

Kiosk lock

Push Apple's App Lock payload, which consoles name differently: Jamf: Configuration Profiles › Single App Mode, by bundle ID. Intune: Device restrictions › Kiosk › App to run: Managed App › pick Bored Room (Intune doesn't take a bundle ID here). Iru: the App Lock library item, by bundle ID. Mosyle: Profiles › Single App Mode. Suggested options: leave touch on; disable the sleep/wake button, volume buttons, and auto-lock (Intune words these as "Block …").

If the download fails, the last good image stays; until the first one arrives, background (or the current background) shows.

If you push none of the three hours keys, the default schedule applies: Monday to Friday, 07:00 to 17:00. Any one of them locks the whole Hours section on the device. A value the app can't parse is ignored (the default stays), so check the board after the first push. All string keys must be plist strings; pin as an integer is ignored.

With serviceAccountKey, calendarId, roomName, and pin set, the app skips setup entirely and boots to the board. Setting only some keys is fine; the app asks for the rest on first launch and locks what you pushed.

An AppConfig Community spec file for consoles that import one is at BoredRoom.appconfig.xml.

Example: property list (Jamf, Mosyle, Iru, most consoles)

Paste as the app's configuration dictionary: Jamf: Mobile Device Apps › the app › App Configuration › Preferences. Mosyle: Apps › the app › Managed App Configuration. Iru: the App Store app library item › Set app configuration. Where the console supports variables, one profile can cover every room: Jamf substitutes $DEVICENAME, $SERIALNUMBER, $ROOM and $EXTENSIONATTRIBUTE_n (put the calendar ID in an extension attribute); Mosyle has %DeviceName% and %SerialNumber%. Iru has no variables, so it's one library item per room. Test a calendar ID through a variable once; the @ has to come through unescaped.

Intune's "Enter XML data" option accepts the <dict> above verbatim (no <plist> wrapper). Intune substitutes {{serialnumber}} and {{deviceid}} but has no device-name token, so one policy per room is the practical pattern there.

Scoping pattern

One profile per room (or one profile with device variables on Jamf or Mosyle), scoped to that room's iPad by serial or device group. The service account key and the PIN are identical across rooms; only calendarId and roomName change. A spreadsheet with serial, room name, and calendar ID is all you need to onboard 40 rooms.

Verification

  1. Push the app and the configuration to one iPad. On launch it should go straight to the board for the configured room.
  2. Hold the bottom-right corner › PIN › Settings. A banner reads "Some settings are managed by your organization" and managed rows are read-only.
  3. Create a test meeting in the room; it appears within 60 seconds.
  4. Push activeHours with an end a few minutes away. The board fades to black at that minute; a touch brings it back for a minute. Push the real hours.

Security notes

  • The service account key grants exactly what you shared: read (or write) on those room calendars, nothing else. It's stored in the iPad's keychain. Rotate it from Cloud Console (new key, delete old, push the new value); the app picks up the change within a minute while it's on screen, and on next launch otherwise.
  • No Bored Room servers are involved. The iPad talks to oauth2.googleapis.com and www.googleapis.com only. Allow those if you filter egress.
  • Full details: privacy policy.

If something's off

  • App shows setup instead of the board. One of the four core keys is missing or the dictionary isn't reaching the app. Check the profile is scoped to the device and the bundle ID matches.
  • "That file isn't a service account key" at launch. The serviceAccountKey value is truncated or not valid base64/JSON. Re-paste.
  • No rooms / 403. The room isn't shared with the service account, or the admin sharing setting is still at free/busy.
  • Board shows "Can't read this room's calendar anymore." calendarId is wrong or the share was removed.
  • Board is dark during the day. activeDays or activeHours is wrong for that iPad's time zone, or the value didn't parse (check the format) and the default Mon–Fri 07:00–17:00 is in effect.
  • Someone forgot the PIN. Change the pin value in the profile; the app picks it up within a minute while it's on screen. The "Forgot PIN?" button on the device tells them to ask you.
