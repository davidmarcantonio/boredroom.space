Deploy through your MDM

For IT teams with a device console. Push the app, the kiosk lock, and every setting including the room and the credential. An iPad goes from the box to the board with nobody touching it.

Print this page with ⌘P. Links print with their addresses.

Overview

  1. Google: one service account, shared with every room. (Once.)
  2. Apple Business Manager: buy N copies of Bored Room, assign to your MDM. (Once.)
  3. MDM: app with device-based assignment, a Single App Mode payload, and Managed App Configuration per iPad or per group. (Once per profile; then scoping.)

Bored Room reads the standard Managed App Configuration dictionary (com.apple.configuration.managed). Every key is optional. Any key you set is locked on the device: the matching row in Settings shows the value but can't be changed from the iPad.

Part 1: Google

Full click-by-click in the by-hand guide. Summary:

  1. Cloud Console › project › enable Google Calendar API › IAM & Admin › Service Accounts › create (no roles) › Keys › Add key › JSON. Keep the file; it's the credential you'll push.
  2. Admin console › Apps › Google Workspace › Calendar › Sharing settings › External sharing options for secondary calendars › "Share all information, but outsiders cannot change calendars" (or "…and outsiders can change calendars" if you'll enable booking).
  3. Share each room with the service account email: See all event details, or Make changes to events for booking. Do this in Google Calendar (room › Settings and sharing) or with the Calendar API's acl.insert (role reader or writer) if you're scripting many rooms.

Part 2: Apple Business Manager

  1. Apps and Books › Bored Room › quantity › Get. 99¢ per copy.
  2. Assign the licenses to the location your MDM server token belongs to.
  3. In the MDM, sync Apps and Books so the app appears in your catalog.

Part 3: MDM configuration

App

  • Bundle ID: com.dmarcantonio.RoomBoard (the App Store name is Bored Room; the bundle ID predates the rename).
  • Distribution: device-based. The iPads need no Apple ID.
  • Automatic updates: on. Remove app on unenrollment: your policy.

Kiosk lock

Single App Mode requires supervision; use Automated Device Enrollment or Configurator to supervise. Then push a Single App Mode payload (Jamf: Configuration Profile › Single App Mode; Intune: Device restrictions › Kiosk; Mosyle/Kandji: Kiosk/Single App) targeting com.dmarcantonio.RoomBoard. Suggested options: touch on, sleep/wake button off, volume buttons off, auto-lock disabled.

With serviceAccountKey, calendarId, roomName, and pin set, the app skips setup entirely and boots to the board. Setting only some keys is fine; the app asks for the rest on first launch and locks what you pushed.

Scoping pattern

One profile per room (or one profile with device variables), scoped to that room's iPad by serial or device group. The service account key and the PIN are identical across rooms; only calendarId and roomName change. A spreadsheet with serial, room name, and calendar ID is all you need to onboard 40 rooms.

Verification

  1. Push the app and the configuration to one iPad. On launch it should go straight to the board for the configured room.
  2. Hold the bottom-right corner › PIN › Settings. A banner reads "Some settings are managed by your organization" and managed rows are read-only.
  3. Create a test meeting in the room; it appears within 60 seconds.

Security notes

  • The service account key grants exactly what you shared: read (or write) on those room calendars, nothing else. It's stored in the iPad's keychain. Rotate it from Cloud Console (new key, delete old, push the new value); the app picks up the change on next launch.
  • No Bored Room servers are involved. The iPad talks to oauth2.googleapis.com and www.googleapis.com only. Allow those if you filter egress.
  • Full details: privacy policy.

If something's off

  • App shows setup instead of the board. One of the four core keys is missing or the dictionary isn't reaching the app. Check the profile is scoped to the device and the bundle ID matches.
  • "That file isn't a service account key" at launch. The serviceAccountKey value is truncated or not valid base64/JSON. Re-paste.
  • No rooms / 403. The room isn't shared with the service account, or the admin sharing setting is still at free/busy.
  • Board shows "Can't read this room's calendar anymore." calendarId is wrong or the share was removed.
